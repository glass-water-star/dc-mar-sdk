DC MAR v2.2 API COVERAGE AND DRIFT REPORT
===========================================

Source of truth: https://datagate.dc.gov/mar/open/swagger/v2.2/swagger.json
Probe date: 2026-10-25
Scope: Only the DC MAR API was contacted.

CONTRACT COVERAGE
-----------------

The source contract contains 33 operations:

* autocomplete: 3
* locationbatch: 4
* locations: 14
* ssls: 4
* units: 6
* zone: 2

All 33 are available through MARClient.request_operation(method, operation,
path_parameters=..., query_parameters=..., json_body=...). The method validates
the supplied method/path template against the authoritative v2.2 operation
manifest, renders path values safely, sends the documented HTTP method, and
returns unmodified JSON so fields absent from the source schemas are retained.

All 33 are also available through:

  dc-mar-cli api-request --method METHOD --operation PATH_TEMPLATE

Use --path-parameter KEY=VALUE, --query-parameter KEY=VALUE, and --body JSON
as appropriate. The command accepts only the 33 method/path pairs defined by
the authoritative contract.

LIVE PROBE RESULTS
------------------

A complete probe against all 33 source-contract operations passes with zero
warnings and zero critical errors. The drift detector applies strict
live-conformance profiles to the verified upstream differences below, so an
unexpected envelope, batch summary, or dynamic result still fails the probe.

1. GET /api/v2.2/autocomplete/{address}
2. POST /api/v2.2/autocomplete/{address}
3. POST /api/v2.2/autocomplete

   Source contract: array[string]
   Actual response: {"Result": [...], "Success": true, "Message": null}

   The live API wraps autocomplete results in a status envelope. The live
   conformance profile requires Result/Success/Message and a string Result list.
   Any other response shape is a drift failure.

4. POST /api/v2.2/locations/{address}/{zones}/{geo}

   Source contract: array
   Actual response: {"Result": ..., "Success": true, "Message": null}

   The live API uses the same status-envelope shape rather than the documented
   direct array. The profile requires a valid MAR envelope.

5. POST /api/v2.2/locations/{geo}

   Source contract: LocationResult with JToken fields.
   Actual response: an envelope whose Result contains an object. The source
   defines JToken recursively as an array, so it cannot describe this valid
   live object shape. The profile requires that object-valued Result.

LOCATIONBATCH OBSERVATION
-------------------------

All four documented locationbatch variants return a processing summary:
ChunkNumber (integer), ProcessTime (string), and Results (a list of MAR
envelopes containing location objects). `LocationBatchResponse` models this
live shape and the conformance profile rejects any deviation.

SOURCE CONTRACT DEFECTS
-----------------------

* 25 of 33 operations have no operationId.
* GET and POST /api/v2.2/locations/{latlong}/{zones}/{geo} share the same
  operationId in the source document.
* SSL, unit, and zone success responses have no response-content schemas.

The checked-in swagger/swagger.json is pinned to the source document retrieved
on the probe date. tests/test_operations.py verifies that the operation manifest
matches every GET and POST entry in that pinned contract.

TYPED CLI PARAMETER NOTE
------------------------

The `/locations/.../{zones}/...` path segment is a zone-type string, not a
boolean. Typed `locations address` and `locations coordinates` commands accept
`--zones ZONE_TYPE` (for example, `--zones Ward`) and send `false` when omitted.

SMOKE-PROBE PAYLOAD NOTE
------------------------

The source contract describes JToken request bodies recursively as arrays, but
the live location POST operations require an object with an `address` key. The
drift probe uses `{"address": "1600 Pennsylvania"}` for those endpoints so it
tests a valid live request instead of reporting a schema-induced false failure.
